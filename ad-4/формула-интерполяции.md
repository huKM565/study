# Формула интерполяционного поиска

Из учебника Семахина 2025, формула (6.3), с. 81.

## Формула вычисления предполагаемого индекса

$$
m = L + \frac{(R - L) \cdot (Key - A[L])}{A[R] - A[L]}
$$

Или в линейной записи:

    m = L + (R − L) · (Key − A[L]) / (A[R] − A[L])

## Обозначения

| Символ | Значение |
|--------|----------|
| `A[n]` | массив целых чисел |
| `n`    | размерность массива |
| `Key`  | ключ поиска |
| `L`    | левая граница области поиска |
| `R`    | правая граница области поиска |
| `m`    | предполагаемый индекс искомого элемента |

## Идея

В отличие от двоичного поиска, который делит область пополам `m = (L+R)/2`, интерполяционный поиск **прицеливается** на позицию, пропорциональную значению ключа относительно границ:

- Если `Key` близок к `A[L]` → `m` сдвигается ближе к `L`
- Если `Key` близок к `A[R]` → `m` сдвигается ближе к `R`

Пример: массив `[10, 20, 30, ..., 100]`, ищем `70`. Двоичный поиск начнёт с середины (`50`), а интерполяционный сразу вычислит `m ≈ 6` → `A[6] = 70` — попал с первой попытки.

## Условия применимости

- Массив **отсортирован** по возрастанию.
- Данные распределены **равномерно** (в арифметической прогрессии или близко к ней).

Если данные распределены неравномерно — интерполяционный поиск может работать **хуже** двоичного.

## Сложность

- Среднее число сравнений ≈ `log₂(log₂ n)`
- Асимптотическая сложность — `T(log(log n))`
- Один шаг сокращает область поиска с `n` до `√n` (двоичный — с `n` до `n/2`)
